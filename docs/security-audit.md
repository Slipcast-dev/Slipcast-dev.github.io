## Вывод

В просмотренном прикладном коде не подтверждены эксплуатируемые уязвимости. Сайт собирается статически, без клиентского JavaScript, авторизации, форм, серверных обработчиков и базы данных. Описания из GitHub API проходят стандартное экранирование Astro; ссылки формируются из фиксированного списка проектов, HTML из внешних ответов не вставляется.

Основные обнаруженные пробелы относились к защите цепочки поставки и репозитория. Часть устранена в коде и настройках GitHub. Защита `main` остаётся существенным ограничением: репозиторий сейчас приватный, и API возвращает HTTP 403 с требованием GitHub Pro или публичной видимости. Видимость, тариф и личный аккаунт владельца не изменялись.

Это ограниченный инженерный аудит, не сертификация, не полноценный pentest и не утверждение об отсутствии любых уязвимостей.

## Границы доверия

1. Исходники и lock-файл поступают в read-only задачу сборки на GitHub-hosted runner.
2. npm-зависимости исполняются при сборке, но их lifecycle-скрипты при установке запрещены. Checkout не оставляет Git-токен в config.
3. Скрипт обновления читает только фиксированные публичные проекты по HTTPS; таймаут запроса — 20 секунд. При ошибке снимок не заменяется частично.
4. Отдельная задача публикации получает Pages write и OIDC, не устанавливает npm-пакеты и не исполняет shell-код репозитория.
5. Браузер получает HTML/CSS/SVG/PNG. Production CSP запрещает скрипты, подключения к API, формы, плагины и внешние ресурсы.

## Ограничения и оставшиеся действия

1. **Защита ветки main не включена.** GitHub API возвращает HTTP 403 для branch protection и rulesets из-за тарифа приватного репозитория. После осознанного выбора владельцем подходящего тарифа или публичной видимости нужны запрет force-push/удаления main, обязательный PR и успешный `build`. Для одиночного владельца нельзя бездумно требовать чужое одобрение: оно может заблокировать merge.
2. **GitHub Pages недоступен.** API сайта возвращает 404, публичный адрес отвечает 404. CI показывает предупреждение и пропускает deploy, когда Pages недоступен; ошибки реального deploy не скрываются. Публичная страница сейчас не проверена с новыми защитами.
3. **Нативные secret scanning, push protection и CodeQL не включены.** Проверка показала отключённые/недоступные функции; платные продукты не активировались. Проверка истории по нескольким шаблонам не заменяет полноценный секрет-сканер, высокоэнтропийный анализ и проверку недоступных/удалённых объектов истории.
4. **Ограничения GitHub Pages.** Meta-CSP не задаёт `frame-ancestors`, HSTS, X-Frame-Options или Permissions-Policy. Заголовки ответа 404 принадлежат GitHub, а не сборке сайта. Оценка работающего сайта внешним HTTP-сканером и полный TLS-аудит не выполнены; сканерная оценка не заявляется.
5. **Личный аккаунт.** 2FA/passkey, активные сессии, SSH-ключи, список личных токенов, GitHub Apps/OAuth и доступ к устройству не исследовались. Владелец должен проверить эти настройки самостоятельно.
6. **Конфиденциальный канал сообщений.** Работоспособность Private vulnerability reporting не подтверждена. SECURITY.md не обещает несуществующий адрес или канал; для полноценного публичного проекта владельцу нужен проверенный контакт.

## Поддержка

Ответственный за рассмотрение обновлений и доступов — владелец репозитория. Dependabot PR не объединяются автоматически. Проверять security alerts после обновлений и не реже раза в месяц; повторять аудит после изменения хостинга, видимости или CI и не реже раза в квартал. Календарная автоматизация или внешний мониторинг в рамках этого аудита не создавались.
