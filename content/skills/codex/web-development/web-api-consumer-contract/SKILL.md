# Контракт веб-клиента с API

1. Зафиксируй источник контракта. Используй спецификацию, типы, тесты или предоставленный пример ответа. Укажи, где формат подтверждён и где принято обратимое допущение.
2. Определи минимальный набор полей, который нужен экрану. Укажи допустимое отсутствие поля, представление пустого результата и требования к отмене запроса. Оставь обработку формата у границы получения данных, чтобы это решение было единым для всех состояний интерфейса.
3. Подготовь локальные фикстуры для успешного результата, пустого результата, ошибки сервиса и медленного запроса. Для поиска также проверь, что старый медленный ответ не заменяет новый результат.
4. В штатном тестовом окружении проверь, что пользователь видит осмысленное состояние и может повторить действие. Для изменений схемы запусти тесты совместимости на старом и новом допустимых примерах.

Результат — перечень проверенных условий и фикстуры или тесты, которые запускаются существующей командой проекта.

## В Codex
