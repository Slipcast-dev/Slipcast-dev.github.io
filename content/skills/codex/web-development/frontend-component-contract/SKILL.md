# Реализация веб-компонента

1. Найди ближайший существующий компонент и его токены, тесты и места вызова. Сохрани публичные параметры и события при рефакторинге. При добавлении нового компонента зафиксируй входы, события и состояния, которые реально нужны вызывающему коду.
2. Составь небольшую таблицу «состояние → видимый результат → доступное действие». Для асинхронного компонента отдельно опиши загрузку, пустой результат и ошибку. Если данные приходят повторно, предусмотри защиту состояния от устаревшего ответа.
3. Используй нативную кнопку, ссылку или поле там, где их семантика подходит. Привяжи подпись к полю, сохрани порядок клавиатурного фокуса и проверь перенос длинного текста. Подключай клиентский код только там, где нужна интерактивность.
4. Проверь изменённый компонент через его обычную страницу или существующий стенд. Покажи входное состояние и итог действия на узком и широком экранах. Если браузер недоступен, укажи точные сценарии, которые остались непроверенными.

Результат — изменение компонента, перечень затронутых состояний и краткий отчёт с выполненными проверками.

## В Codex

Прочитай применимые AGENTS.md. Найди существующие рабочие команды в package.json, затем используй обычные средства репозитория для правки и локальной проверки. Если доступен браузер, проверь компонент в интеграции и укажи размер окна.
