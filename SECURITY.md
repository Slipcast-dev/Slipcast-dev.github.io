# Безопасность

Поддерживается актуальная версия основной ветки `main`. Сайт статический: без клиентского JavaScript, авторизации, форм, базы данных и серверных API.

## Сообщение об уязвимости

Не публикуйте секреты, персональные данные и готовые способы эксплуатации в Issues или pull request. Если GitHub показывает кнопку **Security → Report a vulnerability**, используйте её для конфиденциального сообщения владельцу.

На текущем приватном репозитории отдельный канал Private vulnerability reporting не подтверждён. Если кнопки нет и у вас нет согласованного личного канала владельца, создайте Issue с просьбой предоставить безопасный канал связи **без технических подробностей уязвимости**. Срок ответа заранее не гарантируется.

## Защита исходников и CI

- Все прямые GitHub Actions закреплены полным commit SHA; обновляются через Dependabot PR.
- Стандартный `GITHUB_TOKEN` доступен только на чтение. Право Pages и OIDC получают исключительно задачи проверки хостинга и публикации в необходимом объёме.
- Pull request выполняет сборку и тесты без публикации; `pull_request_target` не используется.
- Checkout не сохраняет credentials. `npm ci --ignore-scripts` не запускает lifecycle-скрипты зависимостей при установке.
- CI проверяет типы, HTML, контраст, CSP и ограничения workflow; `npm audit --audit-level=high` блокирует сборку при известных high/critical уязвимостях или ошибке проверки.
- Dependabot alerts и security updates включены. Автоматического merge нет.
- Токены не хранятся в репозитории. При подтверждённой утечке сначала отзовите ключ, затем расследуйте историю; простое удаление строки не устраняет утечку.

## Ограничения

На 27 октября 2026 года GitHub API показывает репозиторий приватным. Защита ветки `main` и Pages недоступны на текущем тарифе. Secret scanning и CodeQL не включены; платные лицензии автоматически не подключались. `CODEOWNERS` не запрещает прямой push.

GitHub Pages не предоставляет этому проекту управление произвольными HTTP-заголовками. CSP передаётся через ранний HTML meta-тег; он не поддерживает `frame-ancestors` и не заменяет серверные HSTS, X-Frame-Options или Permissions-Policy. Для полного контроля заголовков потребуется отдельный поддерживающий их хостинг или прокси; в рамках текущей задачи миграция не выполнялась.

Владелец должен защищать аккаунт GitHub с помощью 2FA/passkey и проверять активные сессии и ключи. Настройки личного аккаунта не проверялись и не менялись.

Результаты аудита и границы проверки: [docs/security-audit.md](docs/security-audit.md).
